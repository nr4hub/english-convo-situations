1

The situation

You have finished developing a website for your university module (example: “UniEvents — an event booking website” built with HTML, CSS, JavaScript, PHP and MySQL). Now you must explain it to your lecturer in a viva — a short oral assessment where you demonstrate the site, explain how it works, and answer questions.

Tip: The lecturer is checking two things: does it work? and do you really understand it? Speak about why you made each decision, not only what you built.
Be honest: Never claim work that is not yours. If you used a library, a tutorial or AI help, say so clearly and explain the part you understand.
2

Plan your viva

Use this 10-minute structure as your skeleton. Shorten each part if your lecturer gives you less time.

TimePartWhat you do
0:00 – 0:45IntroductionName, project title, purpose, target users
0:45 – 2:00Architecture & tech stackFront end, back end, database — and why you chose them
2:00 – 5:00Live demoWalk through the main user journey, then the admin side
5:00 – 7:00Code & databaseShow one key feature: code snippet and tables
7:00 – 8:00Security & testingValidation, passwords, SQL injection, test results
8:00 – 9:00Challenges & improvementsWhat went wrong, what you learned, what you would add
9:00 – 10:00Closing & questionsSummarize and invite questions
Before the viva
  • Run the website locally and test every feature once
  • Have the database, code editor and browser already open
  • Prepare test accounts (user and admin) and sample data
  • Prepare a backup: screenshots or a short screen recording
  • Be ready to explain every file you submitted
  • Practise out loud and time yourself
3

Step 1 — Introduce the project

Start with who you are, what the website does, and who it is for. Keep it under a minute.

Opening
  • Greet the lecturer and introduce yourself
  • Name the project and say its purpose in one sentence
  • Describe the target users
  • Outline what you will show
Introducing your project
You
Good morning, sir. My name is Nero Gunasekara, and today I’ll be presenting my web development project, UniEvents.සුබ උදෑසනක් සර්. මගේ නම නෙරෝ ගුණසේකර, අද මම මගේ web development project එක වන UniEvents ඉදිරිපත් කරනවා.
You
UniEvents is an event booking website that allows students to browse university events and reserve a seat online.UniEvents කියන්නේ සිසුන්ට විශ්වවිද්‍යාල events බලලා online seat එකක් වෙන් කරගන්න ඉඩ දෙන event booking website එකක්.
You
I built it to solve a real problem: at the moment, students register on paper, which is slow and often confusing.මම මේක හැදුවේ සැබෑ ගැටලුවක් විසඳන්න: දැන් සිසුන් paper එකෙන් register වෙන්නේ, ඒක ගොඩක් මන්දගාමී සහ ව්‍යාකූලයි.
You
First, I’ll explain the design and technologies. Then I’ll give a live demo, and finally I’ll talk about security and testing.මුලින්ම design එකයි technologies ගැනයි පැහැදිලි කරනවා. ඊට පස්සේ live demo එකක් දෙනවා, අවසානයේ security සහ testing ගැන කතා කරනවා.

Step 2 — Architecture & tech stack

Explain the big picture first, then justify your choices. Lecturers love hearing the word “because”.

Architecture
  • Show a simple diagram: browser → server → database
  • Name each technology and its role
  • Give one reason for each choice
  • Mention the folder structure briefly
Explaining the tech stack
You
Let me start with the architecture. The front end is built with HTML, CSS and JavaScript, and it communicates with a PHP back end.architecture එකෙන් පටන් ගන්නම්. front end එක HTML, CSS, JavaScript වලින් හදලා, PHP back end එකත් එක්ක communicate වෙනවා.
You
The PHP scripts process the requests and store the data in a MySQL database.PHP scripts requests process කරලා data MySQL database එකේ ගබඩා කරනවා.
You
I chose MySQL because the data is structured — users, events and bookings are related to each other.data structured නිසා මම MySQL තෝරගත්තා — users, events, bookings එකිනෙකට සම්බන්ධයි.
Lecturer
Why did you choose PHP instead of Node.js?ඔබ Node.js වෙනුවට PHP තෝරගත්තේ ඇයි?
You
That’s a good question. We covered PHP in our lectures, and it runs easily on XAMPP, so I could test it quickly on my own laptop. However, I understand that Node.js would also be a good option.හොඳ ප්‍රශ්නයක්. lectures වලදී PHP ඉගැන්නුවා, XAMPP එකේ ලේසියෙන් run වෙන නිසා laptop එකේ ඉක්මනින් test කරන්න පුළුවන් වුණා. ඒත් Node.js කියන්නෙත් හොඳ විකල්පයක් බව මම දන්නවා.

Step 3 — The live demo

Follow one clear user journey. Announce each step, do it slowly, and explain the result. Then show the admin side.

Demo flow
  • Home page → register → log in
  • Browse events → book a seat → see confirmation
  • Switch to the admin account → add or edit an event
  • Show how the data changes in the database
Walking through the demo
You
Now I’m going to show you the website. This is the home page, where students can see the upcoming events.දැන් මම website එක පෙන්නන්නම්. මේ home page එක, මෙතැනින් සිසුන්ට ඉදිරි events බලන්න පුළුවන්.
You
First, I’ll create a new account. As you can see, the form checks that the email address is valid before it accepts it.මුලින්ම අලුත් account එකක් හදනවා. ඔබට පේන විදිහට, email address එක වලංගුදැයි form එක පරීක්ෂා කරලා තමයි පිළිගන්නේ.
You
Next, I’m selecting an event and clicking ‘Book now’. The system shows a confirmation message and reduces the number of available seats.ඊළඟට, event එකක් තෝරලා ‘Book now’ click කරනවා. system එක confirmation message එකක් පෙන්නලා ඉතිරි seats ගණන අඩු කරනවා.
You
Now let me log in as the administrator. Here, I can add a new event, edit the details, or delete an event.දැන් administrator විදිහට login වෙන්නම්. මෙතැනින් අලුත් event එකක් add කරන්න, විස්තර edit කරන්න, නැත්නම් delete කරන්න පුළුවන්.

If I open the database, you can see the new booking has been saved in the bookings table.database එක open කළොත්, අලුත් booking එක bookings table එකේ save වෙලා තියෙනවා පේනවා.

Step 4 — Explain your code & database

Choose one important feature and explain it clearly. Don’t read code line by line — explain the logic in plain English.

Explaining code
  • Open the relevant file and say its name
  • Explain the purpose first, then the steps
  • Use simple words: “this function checks…”, “this query selects…”
  • Show the database tables and their relationships
Explaining a key feature
You
Let me explain the booking feature. This file is called book.php, and its purpose is to save a booking for the logged-in user.booking feature එක පැහැදිලි කරන්නම්. මේ file එකේ නම book.php, ඒකේ අරමුණ login වුණ user ට booking එකක් save කිරීම.
You
First, the script checks whether the user is logged in. If not, it redirects them to the login page.මුලින්ම script එක user login වෙලාද කියලා පරීක්ෂා කරනවා. නැත්නම් login page එකට redirect කරනවා.
You
Then it checks if there are seats available. If there are, it inserts a new record into the bookings table.ඊට පස්සේ seats තියෙනවාද කියලා බලනවා. තියෙනවා නම් bookings table එකට අලුත් record එකක් insert කරනවා.
You
The database has three tables: users, events and bookings. The bookings table connects the other two using foreign keys.database එකේ tables තුනක් තියෙනවා: users, events, bookings. bookings table එක foreign keys මගින් අනිත් දෙක සම්බන්ධ කරනවා.
Lecturer
Can you explain this part of the code?මේ code කොටස පැහැදිලි කරන්න පුළුවන්ද?
You
Yes, of course. This query selects all events where the date is in the future, and it sorts them by date so the nearest event appears first.ඔව්, ඇත්තෙන්ම. මේ query එකෙන් දිනය අනාගතයේ තියෙන සියලු events තෝරලා, ළඟම event එක මුලින් එන්න දිනය අනුව sort කරනවා.

Step 5 — Security & testing

Even a simple university website should show security awareness. Mention the protections you added and how you tested the site.

Security & testing
  • Passwords are hashed — never stored in plain text
  • Prepared statements prevent SQL injection
  • Inputs are validated on both the client and server side
  • Sessions protect admin pages from unauthorised access
  • Mention your test cases and the bugs you fixed
Talking about security and testing
You
Security was an important part of this project. For example, passwords are hashed before they are stored, so even if the database is leaked, the real passwords are not exposed.security මේ project එකේ වැදගත් කොටසක්. උදාහරණයක් විදිහට, passwords store කරන්න කලින් hash කරන නිසා database එක leak වුණත් සැබෑ passwords නිරාවරණය වෙන්නේ නැහැ.
You
I also used prepared statements for every database query. This protects the site against SQL injection attacks.database query හැම එකකටම prepared statements භාවිත කළා. මේකෙන් SQL injection attacks වලින් site එක ආරක්ෂා වෙනවා.
You
To test the website, I created twenty test cases, including invalid emails, empty fields and duplicate bookings. Three of them failed at first, so I fixed those bugs.website එක test කරන්න, වලංගු නැති emails, හිස් fields, duplicate bookings ඇතුළුව test cases විස්සක් හැදුවා. මුලදී ඒවායින් තුනක් fail වුණා, ඒ නිසා ඒ bugs හදුවා.

Step 6 — Challenges, improvements & questions

Show that you can reflect on your work. Then answer questions calmly — it is fine to think before you speak.

Handling questions
  • Listen to the whole question; ask for repetition if needed
  • Pause and think, then answer in 2–4 sentences
  • If you don’t know, say so honestly and explain how you would find out
  • Never argue — respond politely and give your reasons
Reflection and Q&A
You
The biggest challenge was preventing two students from booking the last seat at the same time. I solved it by checking the seat count again inside a database transaction.ලොකුම අභියෝගය වුණේ අන්තිම seat එක සිසුන් දෙදෙනෙක් එකවර book කිරීම වැළැක්වීම. database transaction එකක් ඇතුළේ seat ගණන නැවත පරීක්ෂා කිරීමෙන් එය විසඳුවා.
You
If I had more time, I would add email confirmations and a payment system.මට තව කාලය තිබුණා නම්, email confirmations සහ payment system එකක් එකතු කරනවා.
Lecturer
What would happen if a user entered malicious code in the form?user කෙනෙක් form එකේ malicious code එකක් ඇතුළත් කළොත් මොකද වෙන්නේ?
You
The server validates and sanitises every input, and the output is escaped, so the code would be displayed as plain text instead of running.server එක input හැම එකක්ම validate සහ sanitise කරනවා, output එකත් escape කරන නිසා, code එක run වෙන්නේ නැතුව සාමාන්‍ය text එකක් විදිහට පෙන්වනවා.
Lecturer
Did you write all of this code yourself?මේ code සියල්ලම ඔබම ලිව්වාද?
You
I wrote the booking and login logic myself. For the layout, I used Bootstrap, and I followed the official PHP documentation for password hashing.booking සහ login logic මම ම ලිව්වා. layout එකට Bootstrap භාවිත කළා, password hashing සඳහා නිල PHP documentation අනුගමනය කළා.
Lecturer
Can you explain how the login works?login වැඩ කරන්නේ කොහොමද කියලා පැහැදිලි කරන්න පුළුවන්ද?
You
I’m sorry, could you repeat that? ... Yes — when the user submits the form, the server compares the password with the stored hash. If they match, a session is created.සමාවෙන්න, නැවත කියන්න පුළුවන්ද? ... ඔව් — user form එක submit කළාම, server එක password එක stored hash එකත් එක්ක සසඳනවා. ගැලපෙනවා නම් session එකක් හදනවා.
You
To summarize, UniEvents lets students browse and book events online, with secure login and an admin panel. Thank you for your time. I’m happy to answer any further questions.සාරාංශයක් විදිහට, UniEvents මගින් සිසුන්ට ආරක්ෂිත login එකකින් events online බලලා book කරන්න පුළුවන්, admin panel එකකුත් තියෙනවා. ඔබේ කාලයට ස්තූතියි. තවත් ප්‍රශ්න තියෙනවා නම් පිළිතුරු දෙන්න සතුටුයි.

Grammar focus

The language patterns you need to describe what you built and justify your decisions.

Past simple — what you did during developmentCore tense

Use the past simple for finished actions in the project.

  • I designed the database first, then I built the login page.මම මුලින් database එක design කළා, ඊට පස්සේ login page එක හැදුවා.
  • I fixed three bugs during testing.testing වලදී bugs තුනක් හදුවා.
Present simple — how the system worksDescribing systems

Use the present simple for how the website normally works.

  • The server checks the password and creates a session.server එක password එක පරීක්ෂා කරලා session එකක් හදනවා.
  • Each booking belongs to one user.booking එකක් user කෙනෙකුට අයිතියි.
Because / so / in order to — giving reasonsJustifying

Explain your decisions with reasons and purposes.

  • I used MySQL because the data is related.data සම්බන්ධ නිසා MySQL භාවිත කළා.
  • I hash passwords in order to protect users.users ව ආරක්ෂා කරන්න passwords hash කරනවා.
Second conditional — future improvementsReflection

Use ‘If I had…, I would…’ for unreal or hypothetical situations.

  • If I had more time, I would add email notifications.මට තව කාලය තිබුණා නම්, email notifications එකතු කරනවා.
  • I would use a framework if the project were bigger.project එක ලොකු නම් framework එකක් භාවිත කරනවා.

Common mistakes

Fixes that make your viva answers sound clear and confident.

Common mistakeCorrect versionWhy
I am use PHP for backend.I used PHP for the back end. / I am using PHP…Use the correct tense: past simple for the project; do not say ‘am use’.
This website have a login page.This website has a login page.Third person singular: has.
I did not know to do this feature.I didn’t know how to build this feature.Use ‘know how to + verb’.
The reason is because the data is related.The reason is that the data is related. / I chose it because…Do not use ‘reason’ and ‘because’ together.
If I have more time, I will adding payments.If I had more time, I would add payments.Second conditional: if + past, would + base verb.
I copied it from internet.I adapted it from an online tutorial and I understand how it works.Be honest and professional; mention the source and show understanding.
Sorry, I don’t know. (and silence)I’m not sure, but I would check the documentation to find out.Show your problem-solving approach instead of stopping.
